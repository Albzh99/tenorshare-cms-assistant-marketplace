# 跨站 HTML 学习清单（观察点，不是通用样式）

首次建立站点／语言／文章类型规范时，逐项阅读 2–3 篇同类、已发布旧文章。PoGoskill 文章只能示范“应该观察哪些位置”，其 class、CSS、图片尺寸、下载框、Buy Box、链接、ID 和文案均不能复制给其他站点。每项写入本站 `html-contract.md` 时，标记“固定／可选／无／待确认”，附参考页面 ID 与真实 HTML 片段的文件位置；不能从一个偶然样本推断全站规则。

| 观察点 | 要从本站证据回答的问题 |
| --- | --- |
| 页面骨架 | 内容根节点、容器、模块顺序、页面模板与哪些外层元素由 CMS 自动渲染？正文是否允许内嵌 CSS？ |
| 标题 | H1 是否在正文内？H2/H3 层级、编号、锚点如何写？短标题加粗是否只改包装而不动后文？ |
| 目录 | 有无目录、放在哪里、锚点与标题如何一一对应？是否有 hot/new 标记，图标从哪里来？ |
| 段落与列表 | 普通段落、强调、链接、项目列表和步骤的 HTML 长什么样？哪些原文必须逐字保留？ |
| 图片 | 主图、横图、竖图、手机截图、并排图片的真实盒结构、尺寸、响应式、alt、公开 URL、格式组合是什么？图片上方／下方的说明文字如何排？ |
| 表格 | 包装、宽度、居中、单元格对齐、长表格是否横向滚动、移动端断点如何处理？ |
| 产品区 | 产品介绍、下载按钮／下载框、CTA、购买区／Buy Box 分别是否存在、在什么条件下出现、放在哪里、如何链接？不同设备按钮是否不同？不要预设产品区或下载区必有。 |
| 指南与特殊区 | 使用指南、步骤、视频、FAQ、引用、作者、相关文章、面包屑、结论及本站独有模块由正文还是 CMS 模板负责？视频是嵌入、封面链接还是别的结构，素材来源、尺寸和移动端行为是什么？不存在的模块写“无”。 |
| 内容与字段 | 本站有哪些分类，各自适用的文章类型与目录／URL 是什么？`classify_id`、`classify_page_id` 怎样与旧文核对？作者、产品、相关页和六项 Meta 如何取值，哪些字段由模板要求？ |
| 禁止项 | 哪些 class、层级或模块不得改？哪些旧页面存在例外，是否需要拆成另一种文章类型？ |

为每个固定或可选组件保存一个最小、可读的真实 HTML 样本，并注明适用条件、相对顺序及证据。一个模块在部分参考文章中出现、部分没有时，先判断条件或文章类型差异；不能机械地判为每篇必需，也不能混合冲突结构。样本未出现某模块不自动证明本站完全没有；证据不足时标“待确认”，由运营核实后才能标“无”。规范至少提供：一个完整合格样本、一个删掉本站必需模块的不合格样本、源图及视频等素材到最终 HTML 的对账方式，以及桌面／手机布局检查点。验证器必须通过正样本、拒绝负样本；无法自动判断的设计事项写为人工检查，不伪称已自动验证。

站点规范只保存在该运营电脑的持久化 profile 目录，按站点、语言、文章类型隔离。初建后先展示摘要给运营确认；修订时只备份并修改目标 profile，记录版本、改动原因和确认人／时间，复测后才能重新设为 `ready`。日常上传只读 `ready` 规范，不重新向 CMS 学习旧 HTML；显式要求“更新本站规范”时才重学。
